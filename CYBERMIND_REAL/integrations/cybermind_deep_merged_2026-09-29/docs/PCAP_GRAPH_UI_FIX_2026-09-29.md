# PCAP graph and upload UI check — 2026-09-29

The compact CTU IoT-23 PCAP produces 2,312 nodes and 2,315 edges in the latest observation window. The old SVG placed every node on one ellipse and drew every edge, including continuously animated marks; the result was a solid overlapping ring and poor interaction. It also refreshed the background view every three seconds while the upload dialog was open.

The graph now displays a deterministic connected overview of at most 12 endpoints and 24 representative flows, with the number of displayed versus matching endpoints stated on the card. This is a **visualization limit only**: full graph state and model input are unchanged. Selected hosts remain visible; node labels show the last IP octet inside the circle and the full address below. Removed the continuous graph motion and kept clickable node inspection. Snapshot now freezes the displayed graph until Live is selected again. Upload pauses background polling, then refreshes after the dialog closes.

Built with `npm run build` and published the resulting `frontend/dist` assets to `releases/CYBERMIND/_internal/frontend/dist`. Against the running native EXE, `runtime/verify_graph_ui.cjs` uploaded the demo PCAP twice and confirmed: 12 visible nodes, 15 representative flows, working node detail, working Snapshot/Live controls, successful re-upload, unchanged background while upload was open, and no browser JavaScript errors. Evidence: `runtime/graph_ui_verification/results.json` and `pcap_graph.png`. The EXE remained responsive and returned HTTP 200 from `/api/health` after the passing run.

One separate native-process crash occurred during an earlier repeated test (Windows Application log: `CYBERMIND.exe`, `ntdll.dll`, `0xc0000374` at 11:44:22). The subsequent clean-restart repeat test passed. The crash's cause is not established by this UI fix and should be monitored; a passing browser automation run does not prove the native wrapper cannot crash again.
